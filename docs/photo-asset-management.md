# 后台照片资产管理

开发入口：`http://localhost:3000/admin`。点击“管理我的照片”进入 `/admin/photos`。

## 上传与补充信息

1. 选择 sRGB JPEG，浏览器先做文件与 EXIF 预检查。
2. 后端从原始文件读取 EXIF，再保存私有原件、生成稳定的日期时间与编号文件名，并排队处理展示图。
3. 上传结束自动打开 Metadata 编辑界面；多张上传时先打开本批第一张，其余可从照片库继续编辑。
4. 展示图生成后，JSON 的 width / height 自动更新为最终 display JPEG 的实际尺寸。尚未生成时为 `""`，不会把原件尺寸冒充展示尺寸。
5. 可以保存缺失信息的草稿；补齐相机、镜头、曝光参数和地点后可标记“我已核对”。

新照片的 `file` 使用 `YYYYMMDD-HHMMSS-照片编号.jpg`，`slug` 为去掉扩展名的部分。优先使用拍摄时间，无日期时使用上传时间；生成后修改 metadata 不会再次命名。照片编号至少补齐 6 位，但不是 6 位上限。数据库关系和图片入口仍使用 UUID，与可读文件名分离。

旧照片可通过命名迁移统一格式，旧文件名和 slug 记入 metadata sources；迁移不移动 MinIO 对象、不改变既有 UUID 图片入口，也不改名公开静态文件。`src` 是需要管理员登录的稳定图片入口，不是公开作品 URL。完整规则、兼容边界与维护命令见 [LTS.md](LTS.md)。

## JSON 规则

完整示例见 [photo-metadata.example.json](photo-metadata.example.json)。后台详情的“JSON 信息”可查看、下载当前完整记录；编辑表单是正式修改入口。

- 未知的标量和空标签使用 `""`，不使用 null。嵌套对象始终保留完整子字段；无项目时为 `{ "slug": "", "zh": "", "en": "" }`。
- ISO 为整数，如 `100`；未知时 `""`。焦距、光圈、快门分别如 `50mm`、`f/2.8`、`1/250s`。
- 照片参数展示只使用 `focalLength35mm`（35mm 等效焦距）、光圈、快门、ISO，不显示相机及镜头名称。等效焦距缺失时留空，不拿实际焦距冒充；四项之间不用圆点，保留原有视觉间距。
- tags 有值时为字符串数组，支持中文及英文；当前不生成 AI 英文标签。无标签时 `""`。
- 地点字段支持中英对照。display 由地点、区县、城市、省州、国家依次拼接、去重，禁止直接编辑。英文留空时，预览回退中文。
- 地点建议不超过 18 个汉字；每个地点层级最长 300 字符。
- 省级菜单去掉行政区后缀，城市使用常用建议，仍可输入其他地点。不是完整的全球行政区划数据库。
- 中国及已支持单一时区地点自动填写 IANA 时区；多时区国家、未知地点需手动补充。不按经度猜时区，不调用外部定位服务。geocodeQuery 与 GPS 字段为后续地图功能保留。
- 系列填写稳定的英文/数字/短横线/下划线标识和中文名称后，自动出现在相册分类中。无需为了示例创建“项目 1”“项目 2”空相册。
- order 留空时按上传时间生成稳定默认值；手动填写非负整数可以调整相册顺序。不会改变标识和文件名。
- 保存是完整替换，必须携带全部 key 和当前 version。服务端会再次校验并生成系统字段；不完整、非法、过期版本的请求不会写入数据库。
- 编辑时可按 `Ctrl+S`（macOS 为 `⌘S`）保存。保存后的输入文字与占位提示采用一致的基础样式；未保存的人工修改和 AI 补全有独立状态。

后台记录保存在 `photo_metadata.record`，原有 `values`、原始 EXIF 和翻译记录保留兼容。公开作品的选片范围、图片路径、尺寸和排序仍由 `selected-work.json` 控制；后台上传或加入相册不会自动发布照片。

已在公开目录中、且通过导入来源 `sources.selected_work_file` 明确关联的照片，其标题、替代文本、展示地点、日期时间、35mm 等效焦距、光圈、快门和 ISO 现在通过 `/api/v1/public/selected-work/metadata` 读取后台最新值。接口只投影这些展示字段，不返回 GPS、原始 EXIF、器材记录、私有地址、内部 UUID 或整个 metadata。无法匹配、重复匹配、最近删除中的记录不输出。

首页精选条和中英文 Work 页在打开时读取最新信息；后台保存后通过同源 BroadcastChannel 发送无数据的更新通知，前台重新读取公开接口。切回页面会刷新，可见页面每 5 秒检查，后台标签页不轮询。请求使用 no-store 且不携带管理员 Cookie；空值也会同步，不会用旧 JSON 填回被清空的字段。接口暂不可用时保留最近成功数据，首次打开时可回退静态目录。

这一同步不写回源 JSON、不重新命名或压缩照片，也不承担公开作品的新增/下架。下架公开静态照片仍需修改公开选片目录，不能把后台删除操作当成已完成下架。静态初始内容和离线回退并非实时快照；Netlify 上的前端须部署含此同步功能的版本，并指向当前可用 API。

## 相册与删除

### 已有 Selected Work 入库

在 `apps/api` 目录运行 `python -m app.photos.import_selected_work` 可只读预检；加 `--apply` 才会导入。
脚本核对根目录 `selected_work` 与公开目录 JSON，按文件内容哈希识别重复，建立“精选作品”相册。
已在该相册中的照片不重复导入，也不覆盖后台编辑。旧目录中的地点、日期、参数随新照片导入。
不修改公开照片、原文件及公开目录 JSON。

本批次采用已有精选展示规格：长边最多 2400 px、JPEG Q92，不降低质量，单衍生文件上限 16 MB。
缺少 sRGB 声明的旧文件不绕过校验：使用既有且通过验证的 sRGB 公开衍生图作为处理输入；
原件逐字节保存在私有 `source-original.jpg`，原始 EXIF/GPS 仍单独保留。
`sources.selected_work_file` 记录原目录文件名，`selected_work_original_key`（如有）记录私有原件位置。

- 默认 4 列；五档为 16 / 8 / 4 / 3 / 1。最后一档按原比例显示，不裁切。
- 相册封面独立按上传时间倒序选取：“全部照片”最多 4 张，其他相册最多 1 张。不受相册内部的手动 order 影响。
- 档位切换复用照片节点与已解码图片，通过位置/尺寸动画过渡；优先加载可见及邻近照片，不一次预取整个相册的大图。开启“减少动态效果”时不播放布局动画。
- PC 默认滚轮上下浏览，点击“解锁滚轮缩放”后滚轮改变照片大小；`＋ / −` 始终可用。
- 手机双指缩放切换档位，也可使用按钮；系统浏览器的手势兼容性仍需真机验收。
- 点击照片打开大图与完整信息，再点击“编辑 Metadata”。
- 删除经过确认后移入“最近删除”，原件、展示图和 metadata 保留，可恢复为草稿。本次没有永久清空按钮，也不自动清理文件。
- 正在处理的照片暂不可删除；已发布照片也不能直接删除。

## 现有环境升级

其他开发环境升级前先备份数据库和私有存储；在 `apps/api` 目录执行：

```powershell
.\.venv\Scripts\python -m alembic upgrade head
.\.venv\Scripts\python -m app.photos.backfill_records
```

第二条命令可重复运行，只补全尚无 record 的旧照片，保留原字段和原始 EXIF。旧地点完整原文迁移到 place，不擅自猜测拆分。后续启动仍沿用现有 Docker / FastAPI / Next.js 流程，Web 默认端口 3000。

## 英文智能补全

后端通过 NVIDIA 的兼容 Chat Completions 接口调用 `deepseek-ai/deepseek-v4-flash-0731`。在后端读取的本地环境文件中设置 `TRANSLATION_API_KEY`；不要把密钥发进聊天、放进前端或提交 Git。`.env.example` 仅保留安全占位值。配置后需让 API 重新读取环境。

“补全空缺英文”仅翻译已有中文且英文为空的标题、替代文本、描述、系列名称和地点字段（包含 geocodeQuery）。已有英文不覆盖；GPS、拍摄日期、器材、曝光参数和标签不交给模型补造，也不上传照片或原始 EXIF。点击时相应中文文本会发送给 NVIDIA 服务，私密地点请先确认可以外发。

生成内容先留在编辑表单，未保存时为红色；人工修改某项后，该项恢复普通未保存样式。请求期间已编辑的原文/英文会受到保护，不用过期结果覆盖。只有点击保存或按快捷键才写入数据库；翻译失败不会更改已保存 metadata。真实服务的可用性、额度与翻译质量需配置密钥后单独验收。
